**Методическое замечание (важно для приёмки):** камера ортографическая и без зума
(`src/core/camera.ts:48`, `bootstrap.ts:674-681`), поэтому **объект не уменьшается с расстоянием**.

(a) LOD1 отличается от LOD0 только мелочью (зеркала, фары, антенна) — тогда порог не важен;

что при текущем `streamRadius = 2` почти не даёт экономии.
Выбор варианта фиксирует прораб; в приёмке LOD-04 обязателен для любого варианта.

## 7. E. Производительность и бюджеты

### 7.1 Расчёт tris до запуска (бюджет 200 000, `промпты/00_MASTER.md:23`)

Население: флот до 128 инстансов (`bootstrap.ts:98`), трафик 60 (`src/config/life.ts:163`),
пешеходы 200 (`:264`), копы 8, купол NPC 240 (`npcView.ts:14`). Считаем реалистичный кадр:
~80 машин, 208 NPC, город 33k tris (`docs/releases/M3.1.md:31`).

| Слой | LOD0 (1200/700 tris) | LOD1 (≤40 %) |
|---|---|---|
| 80 машин | 96 000 | 38 400 |
| 208 NPC | 145 600 | 58 240 |
| город + пропсы | ~33 000 | ~33 000 |
| **итого** | **≈ 274 600 → FAIL** | **≈ 129 640 → PASS** |

Причина: оба view-модуля ставят `frustumCulled = false` и не отсекают инстансы по видимости
(`vehicleView.ts:73-75`, `npcView.ts:65-68`), поэтому в буфер уходит всё население, а не то,
что в кадре. Пока геометрия — 12-трисовая коробка, это дёшево; с моделями 400–1500 tris это
блокер. Требование к M7: per-instance дистанционный LOD + отсечение по дистанции/кадру
(раздел 10, BUG-M7-002/003).

## Приложение A. Быстрый инспектор GLB (read-only)

Файл `docs/qa/tools/glb-inspect.mjs` пока не создан — сниппет для первого прогона, когда придут
ассеты. Проверяет ASS-05..09 и LOD-01..02 без Blender и без npm: читает только JSON-чанк GLB.

```js
// node docs/qa/tools/glb-inspect.mjs assets/models/car_sedan_lod0.glb
import { readFileSync } from 'node:fs';

const file = process.argv[2];
const buf = readFileSync(file);
if (buf.readUInt32LE(0) !== 0x46546c67) throw new Error('не GLB');
const jsonLen = buf.readUInt32LE(12);
const gltf = JSON.parse(buf.subarray(20, 20 + jsonLen).toString('utf8'));

let tris = 0;
for (const mesh of gltf.meshes ?? []) {
  for (const prim of mesh.primitives) {
    const count = prim.indices !== undefined
      ? gltf.accessors[prim.indices].count
      : gltf.accessors[prim.attributes.POSITION].count;
    tris += prim.mode === undefined || prim.mode === 4 ? count / 3 : 0;
  }
}
const pos = (gltf.meshes ?? []).flatMap((m) => m.primitives.map((p) => gltf.accessors[p.attributes.POSITION]));
const min = [0, 1, 2].map((i) => Math.min(...pos.map((a) => a.min[i])));
const max = [0, 1, 2].map((i) => Math.max(...pos.map((a) => a.max[i])));
const size = max.map((v, i) => +(v - min[i]).toFixed(3));
const center = max.map((v, i) => +((v + min[i]) / 2).toFixed(3));
console.log({
  file, tris,
  size: { x: size[0], y: size[1], z: size[2] },
  center: { x: center[0], y: center[1], z: center[2] },
  min: { x: min[0], y: min[1], z: min[2] },
  nodeMatrix: (gltf.nodes ?? []).map((n) => n.matrix ?? null).filter(Boolean),
  materials: (gltf.materials ?? []).map((m) => m.name),
  images: (gltf.images ?? []).length,
});
```

Как читать: `tris` → LOD-01; `size` → ASS-05 (таблица 3.1); `min.y` → ASS-06/ASS-07:
для машин и NPC ожидается «pivot в центре» (`min.y ≈ −size.y / 2`, колёса на дне bbox),
для пропсов — «pivot по основанию» (`min.y ≈ 0`; если там `−size.y / 2`, пропс утонет
на полвысоты и это FAIL); `center` по X/Z у машин/NPC должен быть ≈ 0; `z` как наибольшая ось
и кабина впереди → ASS-08; пустой `nodeMatrix` → ASS-09.
Оговорка: bbox считается по аксессорам без учёта трансформов узлов — для одноузловых экспортов
это точно, для многоузловых требует сверки с Blender.
