# TakeMyCar — план тестирования

- **Этап:** M2 «Физика и коллизии» (`docs/ROADMAP.md:25-35`).
- **Версия плана:** 1.1 от 2026-11-24 (1.0 — план на M1-коде `dbdee07`; 1.1 синхронизирован
  с финальной сборкой M2).
- **Автор:** агент `qa`.
- **Базовый коммит:** `05224b9` (v0.3.0, тег `m2`), ветка `main`. План 1.0 писался на
  `dbdee07` (M1, v0.2.0), когда код M2 ещё не был закоммичен.
- **Живая сборка:** https://pavletcheck.github.io/TakeMyCar/, бандл
  `assets/index-BBGYUedy.js` (558 059 Б) — побайтово равна сборке `05224b9`.
- **Итоги прогонов:** `docs/qa/runs/M2-2026-11-24.md`, статусы — `docs/qa/M2-CHECKLIST.md`,
  закрытие дефектов — `docs/qa/M2-AUDIT.md` §7.
- **Источники требований:** `docs/ROADMAP.md`, `docs/ARCHITECTURE.md` §2–§3, §7, ADR 0002, ADR 0003,
  `AGENTS.md` (DoD, бюджеты), `промпты/09_PLATFORM_QA.md`.

## 1. Область

### В области (M2)
1. Игровой цикл: фиксированный шаг 60 Гц, интерполяция рендера, защита от спирали смерти,
   счётчик `overrun` в HUD (ADR 0002:68-71, ARCHITECTURE:176-177).
2. Коллизии: OBB/AABB/circle, spatial hash, итеративный решатель, restitution,
   отсутствие туннелирования на 30 м/с, 300 статических + 50 динамических коллайдеров
   (ADR 0003:73-74, :102-107).
3. Пауза/резюм: набор причин, отсутствие скачков `dt`, сохранность ввода.
4. HUD и диагностика: fps, frame ms, draw calls, tris, colliders, overrun, память GPU.
5. Память: отсутствие утечек при создании/удалении мира и сущностей.
6. Смоук браузеров и мобильных устройств, отсутствие ошибок консоли и 404 ассетов.
7. Живой деплой: HTTP-статус, свежесть бандла, поведение после релиза.

### Вне области (проверяется только на отсутствие регрессий)
Миссии, экономика, трафик, пешеходы, полиция, звук, локализация, SDK Яндекс/VK
(M5–M8). Для M2 они не существуют в коде, поэтому «регресс» = «не появилось ошибок
при загрузке».

### Ограничения текущего прогона (2026-11-24, v0.3.0)

Правила:
- Версии — минимальные; на прогоне ставим последние стабильные и фиксируем фактические в отчёте.
- Headless/SwiftShader для fps **не использовать** (`docs/releases/M1.md:29`).
- Мобильные проверки — только на реальном устройстве; эмуляция DPR в DevTools годится
  лишь для вёрстки, не для fps и не для тача.

Один проход ~3 минуты, выполняется на E1/E3/E4/E5. Поток M2 (меню/миссии появятся в M6,
поэтому шаги «меню» и «сохранение» заменены на «пауза» и «перезагрузка»).

| # | Шаг | Ожидание |
|---|---|---|
| SMK-01 | Открыть URL, дождаться исчезновения `#loading` | лоадер исчезает ≤ 1.5 с на E1/E4; чёрного экрана нет; консоль без ошибок и без предупреждений |
| SMK-02 | HUD | три строки `#stats`: `fps`, `frame … ms`, `logic … ms`, `speed … km/h`; `draw calls`, `tris`, `colliders 24 (dyn 0)`, `entities 1`; `overrun 0 steps`, `debt 0 ms`; `#hint` виден |
| SMK-03 | `W` 3.5 с | разгон до `speed 108 km/h` (maxSpeed 30 м/с, `src/app/bootstrap.ts:36`), машина едет по дороге, камера следует без рывков; промежуточная точка — ~70 км/ч за 1.5 с |
| SMK-04 | `W` + `A` 1 с | поворот влево, радиус на полной скорости ≈ 11.5 м (2.6 рад/с, `bootstrap.ts:39`) |

| SMK-07 | Свернуть вкладку 5 с → вернуть | симуляция стоит, после возврата нет рывка и «прыжка» камеры; ввод не залип (машина не едет сама) |

## 4. Регрессионные кейсы M2

### 4.1 Итеративный решатель
| ID | Кейс | Ожидание |
|---|---|---|
| R-M2-01 | Въезд в угол двух зданий на 60 км/ч | машина не «выстреливает», не проходит сквозь стену, выходит из угла ≤ 1 с (ADR 0003:104-105) |
| R-M2-02 | Прижат к стене, газ в стену 2 с | позиция стабильна: колебание < 0.05 м за 0.5 с; нет дрожания меша |
| R-M2-03 | Скользящий удар под 20–30° | скорость сохраняется вдоль стены (проекция на касательную), а не падает в 4 раза |
| R-M2-04 | Касание на 108 км/ч | отскок/гашение читаемы; нет «прилипания» и остановки с первого кадра контакта |
| R-M2-05 | Два контакта одновременно (стык домов) | нормали усредняются или применяются 2–4 итерации; объект не выталкивается в третий коллайдер |

### 4.2 Отсутствие туннелирования на 30 м/с

## 6. Инструменты

1. **DevTools Performance** — frame time, long tasks, принудительный GC, CPU throttle 6×.
2. **DevTools Memory** — heap snapshots до/после 10 циклов create/destroy, сравнение по классам.
3. **DevTools Network** — 4xx/5xx, размеры, кэш (`Cache-Control: max-age=600` у `index.html`).
4. **`?stress=1`** — 300 невидимых статических коллайдеров (`src/app/bootstrap.ts:222-239`).
5. **Консоль браузера** — `renderer.info.memory` доступен только если появится debug-хэндл;
   на `m2` `window.__tmc` сознательно не добавлен (см. `docs/qa/M2-AUDIT.md` A-07/PERF-10),
   поэтому память смотрим через DevTools → Memory.
6. **HTTP-проверки деплоя** — `curl -o NUL -w "%{http_code}"` по URL и по хэшу бандла
   (сверка SHA-256 живого файла с локальным `dist/`).
7. **Playwright** — план внедрения ниже.

## 7. Автоматизация: Playwright-смоук

**Статус:** не внедрён (проверено и на финальной сборке `05224b9`). В `package.json` нет
`@playwright/test`, каталога `e2e/` нет, в `docs/ci/deploy-workflow.yml` нет шага тестов,
`.github/` отсутствует. Добавление зависимости требует согласования с прорабом
(правило «не добавлять зависимости без ADR»), поэтому `qa` готовит спецификацию,
но не устанавливает пакет.

Целевой спек `e2e/smoke.spec.ts` (создаётся владельцем `core`/`platform` после одобрения):

```ts
import { expect, test } from '@playwright/test';

const BASE = process.env.BASE_URL ?? 'http://127.0.0.1:4173/TakeMyCar/';

test('канвас стартует без ошибок консоли', async ({ page }) => {
  const errors: string[] = [];
  const bad: string[] = [];
  page.on('console', (m) => { if (m.type() === 'error') errors.push(m.text()); });
  page.on('pageerror', (e) => errors.push(String(e)));
  page.on('response', (r) => { if (r.status() >= 400) bad.push(`${r.status()} ${r.url()}`); });

  await page.goto(BASE);
  await expect(page.locator('#loading')).toHaveClass(/hidden/, { timeout: 5000 });
  await expect(page.locator('#game canvas')).toHaveCount(1);
  const box = await page.locator('#game canvas').boundingBox();
  expect(box?.width ?? 0).toBeGreaterThan(100);

  await expect(page.locator('#stats')).toContainText(/colliders 24/);
  await page.keyboard.down('KeyW');
  await page.waitForTimeout(1500);
  await page.keyboard.up('KeyW');
  await expect(page.locator('#stats')).toContainText(/speed [1-9]\d* km\/h/);

  expect(errors).toEqual([]);
  expect(bad).toEqual([]);
});

test('stress-режим поднимает 300 + 50 коллайдеров', async ({ page }) => {
  await page.goto(`${BASE}?stress=1`);
  await expect(page.locator('#stats')).toContainText(/colliders 374 \(dyn 50\)/, { timeout: 5000 });
  await expect(page.locator('#stats')).toContainText(/overrun 0 steps/);
});
```

Ограничения спека: fps в headless недостоверен (`docs/releases/M1.md:29`);
проверяем только старт, канвас, HUD-числа, отсутствие ошибок и 404.

## 9. Критерии приёмки M2 (go/no-go)

1. `npm run typecheck` и `npm run build` зелёные, bundle < 25 МБ gzip.
2. Все P0-проверки из `docs/qa/M2-CHECKLIST.md` — `PASS` на E1, E3, E4, E5.
3. Нет открытых Blocker/High.
4. Бюджеты: 60 fps / frame p95 ≤ 16.6 мс на E1, ≥ 30 fps на E4; draw calls < 150;
   tris < 200k; физика ≤ 2 мс при 374 коллайдерах.
5. 30-минутный соак без роста памяти и без падения fps > 10 %.
6. `overrun` и таймер шага видны в HUD; 10 циклов create/destroy без утечек.
7. Живая ссылка открывается на десктопе и телефоне, бандл совпадает с HEAD,
   в консоли нет ошибок, в Network нет 404.
8. Релиз-ноты `docs/releases/M2.md` и тег `m2` на месте.
