## 3. Детали по критичным пунктам

### A-01. `overrun` отсутствует (High)

`src/core/loop.ts:97-106`:

```ts
while (this.accumulator >= this.fixedStep && steps < this.maxSteps) { ... }
if (steps === this.maxSteps) {
  this.accumulator = 0;      // долг отброшен, счётчика нет
}
```

`src/app/debug.ts` печатает только fps/frame/speed/calls/tris/colliders. Требование
ADR 0002:70 и ARCHITECTURE:715-716 — «факт отбрасывания инкрементит `overrun` в HUD».
Проверка R-M2-20 (блокировка main thread 250 мс) сейчас не может быть принята:
наблюдать нечего. Дополнительно: при `maxFrameDelta = 0.1` и шаге 1/60 достижимо
максимум 6 шагов, поэтому `steps === 8` не наступает никогда — обещанная защита
существует только на бумаге (см. A-09).

### A-02. Решатель и реакция на контакт (High)

`src/app/bootstrap.ts:378-391`:

```ts
for (let i = 0; i < collisionCandidates.length; i += 1) {
  if (circleRect(resolvedX, resolvedZ, CAR_RADIUS, collisionCandidates[i], contact)) {
    resolvedX += contact.nx * contact.depth;
    resolvedZ += contact.nz * contact.depth;
    hit = true;
  }
}
...
if (hit) { car.vx *= 0.25; car.vz *= 0.25; }
```

1. Один проход: второй коллайдер разрешается после первого, но первый не перепроверяется
   → в углу и на стыке двух плит объект может быть вытолкнут обратно в первый коллайдер.
   ADR 0003:73 требует 2–4 итерации и усреднение нормалей.
2. `* 0.25` не различает лобовой удар и касание под 10°: на 108 км/ч касание даёт 27 км/ч
   за один шаг, скольжение вдоль стены исчезает — это читается как «прилипание».
   Нужна проекция скорости на касательную + restitution ≈ 0.2 (ADR 0003:74).
3. `restitution` и тюнинг не вынесены в конфиг (AGENTS §5).

Риск: критерий M2 «300 объектов сталкиваются без просадок» не проверяем, пока поведение
в углах нестабильно; на 374 коллайдерах вероятность стыков выше.

### A-03. Пауза на одном флаге (High)

`src/app/bootstrap.ts:425-442` + `src/core/loop.ts:64-76`. Причины паузы (blur, hidden,
меню, реклама, `game_api_pause`) сведены к булеву значению, поэтому:

- `focus` снимает паузу, даже если игра была остановлена меню или рекламой (M6/M8);
- `visibilitychange(hidden=false)` размораживает игру без проверки фокуса окна;
- нет способа узнать, кто именно держит паузу (`pausedBy`).

Проверка R-M2-24 («две причины») на текущем коде падает по построению. Контракт —
ARCHITECTURE:142-166.

### A-04. Нет teardown (High)

- `attachKeyboard` возвращает `unsubscribe`, но результат отброшен (`bootstrap.ts:80`);
- `window.blur/focus/resize`, `document.visibilitychange` — без снятия (`438-442`, `459`);
- `GameLoop.stop()` есть, но не вызывается (`loop.ts:57-62`);
- `renderer`, геометрии и материалы не `dispose()` (`bootstrap.ts:85-274`);
- `bootstrap()` не идемпотентен: повторный вызов создаст второй canvas и второй RAF.

Требование M2 «отсутствие утечек при destroy» не может быть проверено: метода нет.
План проверки после появления: R-M2-16…R-M2-19.

### A-06. Динамические коллайдеры (High / в работе у `core`)

`SpatialHash` умеет `insert/update/remove`, но в рантайме после старта не вызывается ни
разу (`bootstrap.ts:121-124` — только вставка при генерации). 50 движущихся объектов
M2 отсутствуют, поэтому:
- HUD не покажет 374;
- бюджет «физика ≤ 2 мс при 374» измерить нельзя;
- `rectRect` (динамика-динамика) не задействован (A-20).

### A-07. Инструментарий приёмки (High)

Сейчас измеримы только `renderer.info.render.calls/triangles` и fps по клампленому
времени. Для приёмки M2 нужны:
1. `step ms` (среднее/максимум за 0.5 с) и `phys ms` — бюджет 4 мс / 2 мс;
2. `overrun` — A-01;
3. `renderer.info.memory.geometries/textures` — контроль утечек без DevTools;
4. `?debug=1` → `window.__tmc` с машиной, циклом и рендерером — иначе Playwright не может
   проверить ни туннелирование, ни позицию после удара (сейчас HUD не отдаёт координаты).

### A-08. Знак поворота OBB (Medium, станет High при `angle ≠ 0`)

`src/core/math.ts:146-147` переводит точку в локальные координаты прямоугольника как
`Ry(+θ)`, тогда как нужен обратный поворот:

```ts
const localX = dx * cos + dz * sin;   // ← это прямой поворот
const localZ = -dx * sin + dz * cos;
```

Проверка на числах (node, `three@0.187`):

| Вход | Результат |
|---|---|
| `rect hx=4, hz=1, angle=π/6`; круг `r=1.8` в точке `(3, −1.732)` | — |
| Локальные координаты по коду | `(1.732, −3.000)` → расстояние до прямоугольника **2.000** > 1.8 → **контакта нет** |
| Корректные локальные координаты | `(3.464, 0.000)` → центр **внутри** прямоугольника (distance 0) |
| `THREE.Matrix4().makeRotationY(π/6)` | локальная `+X` → мир `(0.866, −0.500)` — подтверждает нужный знак |

То есть для `angle ≠ 0` (OBB) коллизия «зеркалится»: с одной стороны стены будет
ложный контакт, с другой — проезд сквозь. Сейчас латентно, потому что
`addStaticCollider` передаёт `angle: 0` (`bootstrap.ts:122`), но M2 требует OBB,
а `world` (M3) начнёт отдавать повёрнутые коллайдеры. Нужен юнит-тест на 4 угла и
сверку с матрицей Three.

### A-09. Константы цикла против ADR (Medium)

| Параметр | ADR 0002 / ARCHITECTURE | Код |
|---|---|---|
| `MAX_SUBSTEPS` | 5 | 8 (`bootstrap.ts:18`) |
| `maxFrameDelta` | 0.25 с | 0.1 с (`bootstrap.ts:19`) |
| `overrun` | счётчик | нет |

Следствие: после «сна» ноутбука симуляция догоняет только 100 мс (6 шагов) вместо
заявленных 250 мс, долг отбрасывается без диагностики; ветка `steps === maxSteps`
недостижима и является мёртвым кодом (AGENTS §4). Константы дублируются в двух местах
(`bootstrap.ts:17-19` и дефолты `loop.ts:37-39`) — риск расхождения.

### A-10. Метрика fps (Medium)

`frameDt` клампится (`loop.ts:93`), а `DebugOverlay` суммирует именно его
(`debug.ts:23-29`). Кадр 250 мс учитывается как 100 мс. Пример: три кадра по 16 мс и
один 250 мс → реально 4/0.298 = 13.4 fps, HUD покажет 4/0.148 = 27 fps. Бюджет
«60 fps / frame < 16.6 мс» нельзя подтвердить или опровергнуть по HUD — нужен
DevTools Performance или исправленная метрика.

### A-12. Отсутствие WebGL / потеря контекста (Medium)

`new THREE.WebGLRenderer(...)` вызывается без `try/catch` (`bootstrap.ts:85`).
На устройстве без WebGL2 (старые телефоны, отключённое аппаратное ускорение)
исключение всплывает из `bootstrap()`, `#loading` остаётся с текстом «Загрузка города…»
навсегда, в консоли — необработанная ошибка. Потеря контекста (`webglcontextlost`)
не обрабатывается: цикл продолжает рендерить и печатать ошибки. Для площадок это
«чёрный экран без объяснения».

### A-16. `GTA 2` в описании (Medium, блокирует модерацию)

`index.html:10`: `<meta name="description" content="TakeMyCar — браузерная 3D-игра в духе GTA 2. Pre-alpha." />`,
то же в `package.json:5`. Живая страница отдаёт это описание (проверено HTTP-телом).
`AGENTS.md:49` запрещает IP Rockstar, `промпты/09_PLATFORM_QA.md:48` — «описание без слова
GTA». Правка — одна строка в двух файлах, но зона `platform`/`прораб`, не `qa`.

## 4. Что проверено и замечаний не вызвало

1. **Нулевые аллокации в горячем пути.** `updateCar` не создаёт объектов: `Contact` один
   на всех (`bootstrap.ts:118`), массив кандидатов переиспользуется (`:117,373`),
   `InputState` тоже (`:81,334`). `SpatialHash.collect` пишет в переданный `out`,
   дубликаты отсекаются `stamp` (`spatialHash.ts:106-125`). Это соответствует ADR 0003:71-72.
2. **Туннелирование на 30 м/с отсутствует** при текущих константах: 0.5 м за шаг против
   окна 4.4 м (запас 8.8×). Это заслуга `CAR_RADIUS = 1.8` и `maxSpeed = 30`; при
   изменении любого из них тест нужно пересчитать (R-M2-10).
3. **Интерполяция рендера** реализована корректно: `prev*` пишутся в начале шага,

## 5. Не проверено и почему

| Что | Причина | Как закрыть |
|---|---|---|
| Смоук в браузере, консоль, Network | `[browser.disconnected]` — нет desktop-браузера в сессии | Открыть сессию в приложении с браузером или прогнать вручную по чек-листу |
| fps, frame time, draw calls, tris в живом рендере | то же | E1 + DevTools Performance |
