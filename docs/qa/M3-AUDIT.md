# M3 — статический аудит готовности к переносу города в `world`

- **Аудитор:** агент `qa` (только чтение; `src/**` не правился, ничего не запускалось в фоне).
- **Базовый коммит:** `cd1db3b` (v0.3.1, тег `m2.1`), ветка `main`, рабочее дерево чистое.
- **Состояние кода:** `src/world/**`, `src/render/cityView.ts`, `src/config/world.json`,
  `tools/`, `e2e/` отсутствуют; город строится в `src/app/bootstrap.ts:146-330`.
  Аудит — прогноз рисков переноса, а не поиск багов в существующем мире.
- **Связанные документы:** `docs/qa/M3-TESTPLAN.md` (кейсы), `docs/qa/M2-AUDIT.md`
  (перенесённые дефекты A-03/A-04/A-10…A-15), `docs/ARCHITECTURE.md` §3.4, §4, §7, §8,
  `docs/adr/0003-collider-shape.md`, `промпты/03_WORLD.md`.
- **Что НЕ проверялось:** браузер, fps, память, Playwright, мобильные устройства —
  см. §5. Никаких живых замеров в этом документе нет; все числа — расчёт по коду.

## 1. Итог

| Severity | Кол-во | Что это значит для M3 |

| Low | 3 | гигиена/визуал |

Главные выводы:

1. **Детерминизм сейчас нечем измерить.** Хэша мира нет, `?debug=1` нет, `window.__tmc`
   не добавлялся (осознанное решение M2). Первым делом `world` должен отдать
   `layoutHash` и счётчик времени генерации чанка — иначе кейсы DET-01…03 и CH-07
   невозможно принять (M3-A-02, M3-A-16).
2. **Стриминг чанков упирается в `SpatialHash`, который ключуется по `id`.**
   Сейчас id выдаёт локальный счётчик в `bootstrap.ts`. Если `world` начнёт нумеровать
   коллайдеры по-чанково, `insert` превратится в `update` и один чанк молча «съест»
   коллайдер другого; `remove` при выгрузке снесёт чужой. Это Blocker-класс,
   замаскированный под деталь реализации (M3-A-06, M3-A-07).
3. **Три границы мира захардкожены под 150×150 м**: `BOUND = 75` (кламп машины),
   разметка от `BOUND`, стресс-режим от `BOUND`. При мире 1.2 км машина упрётся
   в невидимую стену на 75 м — критерий «езда по всем дорогам» станет недостижим
   (M3-A-14, M3-A-04).
4. **Контракт данных неполон.** В `ARCHITECTURE.md` используются, но не объявлены
   `MinimapTile`, `PropInstance`, `RoadGraph`; в `Chunk` нет дорожной/тротуарной
   геометрии, в `RoadEdge` нет геометрии полос, нет описания воды. Пока это не
   решено, часть кейсов (RW-01, MM-02, RG-06) не имеет эталона (M3-A-26…M3-A-29).
5. **Бюджет чанка нельзя подтвердить по HUD**: `logic ms` — среднее за 0.5 с,
   всплеск 12 мс даст +0.17 мс при 144 fps. Нужен максимум/отдельный счётчик
   (M3-A-16).

## 3. Разбор ключевых рисков

### 3.1 M3-A-06. Стриминг + id коллайдеров = молчаливая потеря

`src/app/bootstrap.ts:139-144`:

```ts
let nextColliderId = 1;
function addStaticCollider(x, z, hx, hz): void {
  colliderHash.insert({ id: nextColliderId, x, z, hx, hz, angle: 0 });
  nextColliderId += 1;
}
```

`SpatialHash` хранит `records` по `item.id` (`src/core/spatialHash.ts:33,41-56`), а
`insert` при существующем id вызывает `update`, то есть **заменяет** запись, а не
добавляет. Динамика специально ушла в отрицательные id (`registry.ts:260-263`), но
про статику такого правила нет.

Сценарий отказа в M3: `world` выдаёт id «на чанк» (0…N в каждом чанке) →

1. чанк A вставил коллайдер `id 3` в точке X;
2. чанк B вставил коллайдер `id 3` в точке Y → запись A переписана, коллайдер X
   исчез из broadphase (машина проезжает сквозь дом);
3. выгрузка B вызывает `remove({id: 3})` → удаляется и запись, принадлежащая A.

Симптом в тестах: `colliders` не растёт (даже падает), CM-03/CM-04 «невидимые стены
и проезжаемые дома», причём нестабильно — зависит от порядка активации.

Требование: `World` — единственный источник `nextColliderId`, монотонный на весь
сеанс, положительный; QA проверяет уникальность по активным чанкам (CH-06).

### 3.2 M3-A-07. Коллайдеры некуда выгружать

`remove` вызывается только из `EntityRegistry` для динамики (`registry.ts:358-363`).
Для статики в `bootstrap.ts` нет ни одной обратной операции. HUD `colliders`
(`bootstrap.ts:576`) читает `colliderHash.size`, поэтому тест «не растут при движении
по кругу» ловит именно эту утечку — при условии, что `world` явно снимает коллайдеры
выгруженного чанка. Дополнительно нужен инвариант:
`colliderHash.size === Σ(активные чанки) + динамика` (CH-03).

### 3.3 M3-A-14. `BOUND = 75` — невидимая стена посреди города

`src/app/bootstrap.ts:26,470-471`:

```ts
const BOUND = GRID * BLOCK_STEP + BLOCK_HALF;   // 2*32 + 11 = 75
...
car.x = clamp(carBody.x, -BOUND, BOUND);
car.z = clamp(carBody.z, -BOUND, BOUND);
```

Плюс от `BOUND` строятся разметка (`:218-227`) и стресс (`:276-277`). Мир 1.2 км —
это ±600 м; при сохранении константы игрок упрётся в стену, а половина города станет
недостижимой. Замена — `world.bounds` (+ допуск на радиус машины). Тест RW-04/CM-06
без этого не имеет смысла.

### 3.4 M3-A-16. Усреднённый `logicMs` скрывает пики генерации

`bootstrap.ts:540-550` копит `logicMsSum/logicSamples` за окно, `debug.ts:63-67`
делит на число кадров. При 144 fps окно 0.5 с — это ~72 кадра:

| Реальная длительность генерации | Прибавка к HUD `logic` |
|---|---|
| 8 мс | +0.11 мс |
| 12 мс | +0.17 мс |
| 30 мс | +0.42 мс |

На фоне обычных 0.02 мс это выглядит как «шум», хотя кадр уже пропущен. Бюджет
«< 8 мс» принимается только по счётчику максимума/отдельной метке `chunk ms`
(и по `overrun`/`debt`, которые тоже надо смотреть в момент пересечения границы).

### 3.5 M3-A-26/M3-A-27. Контракт `World` не описывает то, что нужно проверять

`ARCHITECTURE.md:356-364`:

```ts
export interface Chunk {
  readonly cx: number;
  readonly cz: number;
  readonly colliders: readonly Collider[];
  readonly props: readonly PropInstance[];   // PropInstance нигде не объявлен
  readonly minimap: MinimapTile;             // MinimapTile нигде не объявлен
  readonly renderRef: number;
}
```

Нет ни дорог, ни тротуаров, ни воды — проверить «дорога под ребром» и «пропсы не на
дороге» можно только косвенно, через мини-карту, у которой тоже нет формата. Для M3
нужно решение `architect`: либо `Chunk` расширяется (`roads`, `sidewalks`, `water`,
`district`), либо эталоном объявляется экспорт графа + мини-карта, и тогда кейсы
формулируются по ним. Пока решение не принято, RW-01/02/03, PR-01, MM-02 —
`BLOCKED` даже при готовом коде.

### 3.6 M3-A-18. draw calls при стриминге

Факт M2: 17 draw calls (10 opaque + 7 shadow), 3.7k tris. Оценка M3 при
3–4 инстанс-мешах на чанк (дороги, здания, пропсы, разметка), каждый с тенью:

| Зона стриминга | Чанков | +draw calls | Итого | Бюджет 150 |
|---|---|---|---|---|
| 3×3 | 9 | ≤ 72 | ~89 | ✅ запас 61 |
| 5×5 | 25 | ≤ 200 | ~217 | ❌ пробит |

Вывод: либо радиус 3×3, либо общие инстанс-меши на все активные чанки (один
`InstancedMesh` на тип, перезапись матриц при стриминге). Бюджет на чанк нужно
зафиксировать в конфиге и проверять HUD-ом на E11/E12.

## 4. Что готово к переносу (замечаний нет)

1. **`Collider`/`Contact` и решатель не зависят от города** — `core/math.ts:19-39`,
   `core/collision.ts:52-122`: `world` может отдавать массив коллайдеров без
   конвертации (ADR 0003).
2. **`SpatialHash` умеет `insert/update/remove` и не аллоцирует в запросах** —
   `core/spatialHash.ts:41-127`; для стриминга не хватает только дисциплины id.
3. **`EntityRegistry` отделяет динамику отрицательными id** и умеет `clear()` —
   `core/registry.ts:250-270`, `:325-340`; основа для teardown мира есть.
4. **Интерполяция и камера не знают о размере мира** — `core/camera.ts:76-101`,
   `bootstrap.ts:553-564`: перенос не ломает сглаживание, нужен только кламп по bounds.
5. **Нулевые аллокации в шаге и рендере** подтверждены в M2 и не зависят от того,
   откуда пришли коллайдеры (`M2-AUDIT.md:236-239`).
6. **Детерминированный RNG уже есть** (`core/rng.ts:9-45`), `Math.random` в `src`
   не встречается (grep, 0 совпадений); нужна только дисциплина потоков.
7. **Сборка/деплой стабильны**, бандл 141 кБ gzip — запас под код `world` большой.

## 6. Требования к M3 до начала приёмки

Чек-лист для `world`/`architect`/`core` (не правки QA, а условия, без которых
прогон не начнётся):

1. `World.layoutHash` + отладочный вывод (HUD-строка и `window.__tmc` под `?debug=1`).
2. `worldGenMaxMs`, `worldGenN`, `worldUpdateMs` в HUD/хэндле.
3. Общий монотонный `nextColliderId` в `World`, disjoint с динамикой (отрицательные id).
4. Явная выгрузка коллайдеров чанка; инвариант
   `hash.size === Σ активных чанков + динамика`.
5. `?seed=N` читается один раз в `app` и передаётся в `createWorld`; дефолт — из конфига.
6. Кламп машины и разметка — от `world.bounds`, а не от `BOUND`.
7. Спавн/`R` — из `querySpawnPoints`, не константа `(16, 2)`.
8. Решение по радиусу стриминга и бюджету draw calls на чанк (≤ 3 или общий инстансинг).
9. Объявленные типы `MinimapTile`, `PropInstance`, `RoadGraph`, коды тайлов, признак
   воды и флаг `collidable` у пропса.
10. API полос (центры/направление) в `RoadGraph` до M5.
11. `?stress=1` перебазирован на `world.bounds`/активные чанки, новый baseline в чек-листе.
12. (Желательно) `tools/build/check-imports.mjs` в `npm run typecheck` —
    `docs/ARCHITECTURE.md:610-618` (задача M2, не выполнена).
