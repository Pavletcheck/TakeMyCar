# ADR 0003 — Форма коллайдера и широкая фаза: один `Rect`, круг как сторона запроса

- **Статус:** принято
- **Дата:** 2026-11-23
- **Этап:** M2 (проектирование в M1, реализация при переносе `main.ts`)
- **Связано:** `docs/ARCHITECTURE.md` §3.4, ADR 0001
- **Заменяет / заменено:** —

## Контекст

Коллайдеры города нужны как минимум трём зонам: `core` (решатель), `world`
(генерация зданий и пропсов), `vehicle`/`life` (запросы «куда я врезался»).
В прототипе `src/main.ts:15` форма объявлена локально (`type Rect = { x, z, hx, hz }`),
а город и коллизии строятся двумя параллельными массивами (`src/main.ts:95–124`) —
это уже привело к тому, что данные домов и их коллизии живут отдельно.

Одновременно `core/math.ts` уже реализует (`circleRect`, `rectRect` через SAT)
прямоугольник с **опциональным** `angle`: при `angle = 0` это AABB, при `angle ≠ 0` — OBB.
Круг в этой модели — не статический объект мира, а вторая сторона запроса: машина,
пешеход, пуля описываются радиусом и позицией.

Нужно выбрать одну форму, чтобы `world` не придумал свою, а `systems` не писали
switch по `kind`.

## Варианты

### A. Размеченное объединение `{ kind: 'aabb' | 'obb' | 'circle' }` — отклонено

- Плюсы: явно читается, легко расширяется круглыми коллайдерами и слоями.
- Минусы: каждый потребитель пишет `switch (c.kind)`; три почти одинаковых ветки
  в hot-path решателя; лишняя ветка в каждом кадре; `angle` дублирует `kind`
  (AABB — это OBB с нулевым углом).

### B. Один `Rect` + опциональный `angle`, круг — только в запросе — **выбрано**

```ts
export interface Rect { x: number; z: number; hx: number; hz: number; angle?: number }
export interface Collider extends Rect { id: number }
export function circleRect(cx, cz, radius, rect, contact: Contact): boolean
export function rectRect(a: Rect, b: Rect): boolean
```

- Плюсы: одна проверка в горячем цикле; AABB — частный случай без ветвления
  (`angle === 0` уже обрабатывается отдельной веткой внутри); `id` нужен
  `spatialHash` и дедупликации контактов; `Contact` (`nx, nz, depth`) пишется в
  переиспользуемый объект — ноль аллокаций.
- Минусы: круглые статические препятствия (цистерны, клумбы) аппроксимируются
  квадратом — для top-down это незаметно при 1–2 м.

### C. Три отдельных типа `Aabb`, `Obb`, `Circle` с перегрузками решателя — отклонено

- Плюсы: максимум точности.
- Минусы: комбинаторный рост числа функций (`circle-circle`, `circle-obb`,
  `obb-obb`, `aabb-obb`…), дублирование кода, тяжело тестировать. Для аркады
  избыточно.

## Решение

1. **Единственная форма статического коллайдера — `Collider` (`Rect` + `id`)
   из `src/core/math.ts`.** Локальные объявления `Rect` в других модулях запрещены.
2. **`angle` опционален и по умолчанию 0** — это AABB. Повёрнутые здания и
   барьеры используют `angle`, но не создают отдельного типа.
3. **Круг — сторона запроса, а не хранимый коллайдер.** Динамика (машина, пешеход,
   пуля) описывается центром и радиусом; широкая фаза возвращает прямоугольники,
   узкая — `circleRect(...)`, результат в `Contact`.
4. **`id` уникален в пределах broadphase** (не обязательно `EntityId`): по нему
   `SpatialHash` хранит запись и отсекает дубликаты в запросе через `stamp`.
5. **Слои/маски пока не вводятся.** Когда появятся (пули не бьют по разметке,
   вода не блокирует лодки) — поле `layer` добавляется в `Collider` отдельным ADR,
   а не «на будущее».
6. **Ноль аллокаций в hot-path:** `circleRect` заполняет `Contact`, `rectRect`
   возвращает `boolean`, `queryColliders` пишет в переданный `out`.
7. **Проникновение разрешается по нормали на глубину `depth`**, 2–4 итерации,
   restitution ≈ 0.2 (конфиг `tuning.json`).

## Последствия

Положительные:

- `world` отдаёт `Chunk.colliders: readonly Collider[]`, `core` потребляет их без
  конвертации, `vehicle` не знает, из чего построен дом.
- Один тип — одни тесты: SAT, circle-rect из угла, «центр внутри прямоугольника»,
  стабильность на стыке двух зданий.
- AABB-путь (основная масса зданий) не платит за поворот.

Отрицательные / цена:

- Круглые препятствия приближаются квадратом; при радиусе > 3 м это может быть
  заметно — тогда объект описывается OBB, а не кругом.
- Вращение (`angle`) должно быть согласовано с рендером: меш и коллайдер
  поворачиваются одним и тем же углом из одних данных, иначе «въезжаешь в воздух».

Правила для ревью:

1. В `src/world/**` и `src/systems/**` нет собственных описаний прямоугольника.
2. `circleRect`/`rectRect` не вызываются в варианте, возвращающем объект.
3. Каждый `Collider` в чанке имеет уникальный `id`, иначе hash склеит записи.
4. `angle` в чанке либо 0 (не задан), либо явный: `undefined` и `0` эквивалентны.

## Проверка

- M2: 300 статических коллайдеров + 50 движущихся, физика < 2 мс, ноль GC-пиков
  в `Performance` при 10-секундном прогоне.
- Автотест: машина, зажатая между двумя зданиями под углом, не «выстреливает» и
  не застревает; выход из угла ≤ 1 с.
- Тест «центр внутри прямоугольника»: объект выталкивается по минимальной оси,
  а не телепортируется на край.
